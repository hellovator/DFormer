DFormer 科研学习与实验路线指南

> 当前研究对象：DFormer 原始版本（ICLR 2024），不是 DFormerv2 或
> DFormer++。
> 本文记录学习约定、源码理解要点、科研原则和阶段计划。它不代表模型已完成复现或取得改进结果。

## 1. 项目目标与现实约束

目标是在有限周期内：理解模型、完成可行的构建与前向验证、尽可能建立可信基线、提出一个可验证的改进假设、开展对照实验并整理成果。重点是形成真实、完整、能够讲清楚的科研经历，而不是无限增加模块。

当前环境：Windows、16 GB 内存、CPU 版
PyTorch，`torch.cuda.is_available()` 为 `False`，没有可用 NVIDIA
独立显卡。官方训练入口使用 CUDA、AMP
和分布式训练相关逻辑。完整训练应优先考虑实验室 GPU 或合适的云
GPU；不要在当前 CPU 环境盲目启动大规模训练。

DFormer 独立于 SemHash
项目管理。官方源码与个人修改必须明确区分，不把官方代码描述成个人原创，也不把局部运行成功说成完整复现。

## 2. 学习约定

### 每次只推进一个小任务

- 默认一次只安排一个小任务，通常是一条 PowerShell 命令或一小段代码。
- 先解释为什么做、命令或代码的作用、预期结果。
- 用户执行并反馈后，再解释结果并决定下一步。
- 不一次性布置大量命令，不要求初学者独立完成尚未讲解的复杂修改。

### 代码讲解回答三个问题

1. 是什么：变量、函数、模块分别是什么？
2. 为什么：为什么需要它？为什么采用这种写法？
3. 有什么作用：它在整个模型数据流中处于什么位置？

涉及张量时解释形状变化：`B` 是批次大小，`C` 是通道数，`H` 是高度，`W`
是宽度。

### 循序渐进

认识模块 → 阅读小段源码 → 观察输入输出和 Shape → 用自己的话讲清楚 →
理解充分后再做小修改和实验设计。

不要求背代码或变量名。理解模型主线、解释关键模块、分析实验结果，比默写代码重要。遇到不懂的地方换直白方式解释；不重复已完成工作；不为读完所有源码而无止境挖掘；需要休息时先总结，不追加任务。

## 3. DFormer 模型结构主线

DFormer 用于 RGB-D 语义分割。RGB 提供颜色、纹理和外观信息；Depth
提供距离和空间结构信息。模型为图像中的像素预测语义类别。

**RGB + Depth 输入 → 双模态 Encoder 提取并交互特征 → Decoder
整合多尺度特征 → 分类层输出像素类别。**

### 输入与数据处理

主要位置：`utils/dataloader/`

负责读取 RGB、Depth、Label，执行预处理和数据增强，并通过 DataLoader
按批次提供数据。

当前阅读的 NYUDepthv2 配置： - RGB：`RGB` 目录，`.jpg` - Depth：`Depth`
目录，`.png` - Label：`Label` 目录，`.png` -
训练图像数：795；评估图像数：654 - 类别数：40；忽略标签：255（不是第 41
类）

Label 是训练损失和评估所需的真实标注，不是普通推理时必需的输入。

### DFormer Encoder

主要位置：`models/encoders/DFormer.py`

RGB 和 Depth
分别经过各自的初始特征提取路径、下采样和多阶段特征提取，并在多个 Block
中交互。DFormer-Large 当前通道配置：

阶段        RGB 通道   Depth 通道

---

Stage 1           96           48
Stage 2          192           96
Stage 3          288          144
Stage 4          576          288

关键点：不是简单把 RGB 与 Depth
拼成四通道图像；两种模态有各自的特征路径，并在编码过程中交互。

### Block：双模态交互

主要位置：`models/encoders/DFormer.py` 中的 `Block`

已阅读的关键结构： - `e_fore`、`e_back`：参与 Depth 特征映射和交互。 -
`q`、`q_cut`、`l`、`conv`、`a`：参与 RGB 特征变换和交互计算。 -
`cutted_x * x_e`：逐元素相乘，利用深度相关特征调制 RGB 特征。 -
`window != 0`
分支：组合相关信息，通过池化、线性映射和注意力计算进行交互。 -
`proj`：对融合后的特征进行投影。 - `proj_e`：在相应条件下更新 Depth
特征。

核心理解：Depth 在 Encoder 内部参与 RGB
特征交互；当前读到的前向逻辑收集各阶段 RGB 特征供解码头使用，Depth
不作为一组独立多尺度特征直接送入 HAM 解码头。

### EncoderDecoder

主要位置：`models/builder.py`

模型组织中心：根据配置创建 Encoder 和 Decoder，接收
RGB/Depth，调用编码器和解码头，调整预测尺寸；有标签时计算训练损失。

### LightHamHead

主要位置：`models/decoders/ham_head.py`

当前 DFormer-Large 配置使用 Stage 2、3、4 的 RGB
特征：选择特征、统一空间尺寸、按通道拼接、压缩通道、经过 Hamburger
处理、调整特征并输出类别分数。

拼接通道数为 `192 + 288 + 576 = 1056`，随后压缩到 512。解码头直接接收
Encoder 输出的 RGB 多尺度特征，但这些 RGB 特征已在 Encoder 中受到 Depth
交互影响。

### Hamburger 与 NMF2D

主要位置：`models/decoders/ham_head.py`

Hamburger 主要流程：`ham_in`（1×1 卷积）→ ReLU → NMF2D → `ham_out`（1×1
卷积）→ 残差相加 → ReLU。

NMF2D 的主要思路：将特征整理成矩阵、初始化 Bases、计算
Coefficients、迭代更新系数和基矩阵、重构特征，再恢复为特征图。

直观理解：尝试用一组基础特征及其组合系数表示输入特征，再通过重构得到处理后的表示。

**严谨性提醒：** 不能仅凭名称断言 NMF2D 一定比 Self-Attention
更快、更好或更省显存。实际成本取决于矩阵形状、分解秩、迭代次数和实现方式。需要结合论文、代码和公平实验比较。当前源码中
Bases 初始化路径存在 CUDA 相关设置，CPU 前向兼容性尚待验证。

### 分类预测层

主要位置：`models/decoders/decode_head.py`

`cls_seg` 使用 1×1 卷积将特征映射为类别分数。NYUDepthv2 配置为 40
类，对应 40 个类别通道，再得到像素级预测。

## 4. 训练流程及外围模块

模块         主要位置                      职责

---

配置         `local_configs/NYUDepthv2/`   模型、数据集、优化器和训练参数
数据加载     `utils/dataloader/`           读取 RGB、Depth、Label
模型构建     `models/builder.py`           组装 Encoder 和 Decoder
训练入口     `utils/train.py`              创建训练组件并执行训练循环
优化器配置   `utils/init_func.py` 等       参数分组和优化器创建
学习率策略   `utils/lr_policy.py`          调整学习率
评估与保存   训练相关代码                  评估模型、保存权重

已读训练数据流：`minibatch["data"]` 是 RGB，`minibatch["modal_x"]` 是
Depth，`minibatch["label"]` 是真实标签。训练循环将数据送入模型，计算
Loss，再反向传播并更新参数。

官方训练入口使用 `.cuda()`、CUDA AMP、CUDA
同步和分布式训练逻辑，因此当前 CPU
环境不能直接照搬官方命令进行完整训练。

## 5. 科研原则：从理解到验证

遵循闭环：

1. 理解原始模块：是什么、解决什么问题、输入输出是什么？
2. 发现潜在局限：什么场景下可能不足？有什么证据？
3. 提出假设：为什么某个改动可能改善问题？
4. 设计公平实验：基线、对照组和必要的消融实验。
5. 分析真实结果：指标、可视化和错误案例是否支持假设？
6. 形成结论：如实报告提升、下降、失败和限制。

### 消融实验注意事项

- 不应只注释一行代码就认为完成消融。
- 删除模块后要保证结构合理、输入输出维度匹配。
- 尽量保持数据划分、训练策略、随机种子、训练轮数和评价方式一致。
- 每次优先改变一个因素，便于判断变化来源。
- 结构或训练条件有变化时必须记录。

### 对新模块保持审慎

PFESA、边缘损失、傅里叶变换等只能作为未来调研候选方向，不是已确定的创新方案。原始模型理解、构建与前向验证、可行条件下的基线建立、相关论文调研和研究假设明确之前，不直接把这些模块加入模型。

### 结果报告底线

- 不编造指标、实验结果或论文结论。
- 不隐瞒负面结果和失败实验。
- 区分官方实现、个人修改和实验设置。
- 小规模或不完整实验明确标注限制。
- 不把相关性直接说成因果关系。
- 只有实验支持的结论才能写成研究结论。

## 8. GitHub 文档管理

不要把所有笔记和实验记录塞进 `README.md`。建议逐步形成：

```text
DFormer/
├── README.md
├── docs/
│   ├── research/
│   │   ├── research_learning_guide.md
│   │   ├── model_architecture_notes.md
│   │   └── experiment_plan.md
│   └── experiments/
│       ├── experiment_log.md
│       └── results_analysis.md
├── models/
├── utils/
└── local_configs/
```

文件职责： -
`README.md`：项目简介、来源、环境、运行方式、数据准备、主要结果和文档入口。 -
`research_learning_guide.md`：学习约定、科研原则和总体阶段计划。 -
`model_architecture_notes.md`：源码结构和模块阅读笔记。 -
`experiment_plan.md`：研究问题、假设、实验组和评价方案。 -
`experiment_log.md`：每次实验的详细记录。 -
`results_analysis.md`：阶段性结果、错误案例和结论。

README 文档入口可写为：

```markdown
## Documentation

- [Research Learning Guide](docs/research/research_learning_guide.md)
- [Model Architecture Notes](docs/research/model_architecture_notes.md)
- [Experiment Plan](docs/research/experiment_plan.md)
- [Experiment Log](docs/experiments/experiment_log.md)
- [Results Analysis](docs/experiments/results_analysis.md)
```

GitHub 上传采用网页操作，不要求使用 Git 命令行。先将本指南上传到
`docs/research/research_learning_guide.md`；其他文档随着项目进展再创建。上传前检查文件名、目录和
Markdown 预览。

## 9. 当前进度与下一步

### 已完成的学习工作

- 阅读 DFormer-Large 的 NYUDepthv2 配置。
- 理解 `EncoderDecoder` 的主要职责和前向数据流。
- 阅读 DFormer Encoder 的双分支结构与多阶段特征提取。
- 阅读 Block 中 RGB-D 特征交互的主要逻辑。
- 阅读 `BaseDecodeHead` 和 `LightHamHead` 的主要结构。
- 理解 Hamburger 与 NMF2D 的主要计算流程。
- 阅读训练入口中的数据流、Loss、优化器和 CUDA 训练逻辑。
- 整理源码阅读笔记。

### 尚未完成，不能提前宣称完成

- 数据集和预训练权重完整性确认。
- 当前环境下模型构建的实际验证。
- NMF2D 等模块的 CPU 前向兼容性验证。
- 最小前向验证。
- 完整训练或官方基线复现。
- 新模块改进实验及其有效性验证。

### 下一步只做一件事

进入模型构建验证：先检查配置、权重和数据路径是否齐全，再根据实际结果确定最小验证方式。一次只推进一个小任务，不直接启动完整训练。

## 10. 最重要的提醒

- 不用背代码，先理解数据流和模块作用。
- 不追求一次看懂所有细节。
- 不把模型跑通、模型复现和科研创新混为一谈。
- 基线尚未确认前，不同时引入多个新模块。
- 不预设实验一定提升。
- 真实记录每一次成功、失败和限制。
- 最终能够解释研究问题、模型工作方式、实验过程、结果含义和不足。

**先理解，再验证；先建立基线，再提出改进；最后用实验而不是猜测得出结论。
